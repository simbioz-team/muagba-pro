# muagba-pro

База окружения для мультиагентной разработки. Одна основа для всех проектов:
рамки, права, хуки, роли агентов и скилы настройки.

Репозиторий состоит из двух частей, и разделение между ними принципиальное:

| Часть | Что это | Как обновляется |
|---|---|---|
| `plugins/muagba-base/` | **Механика.** Хуки, роли, скилы. Одинакова везде. | Централизованно — обновление плагина прилетает во все проекты |
| `template/` | **Каркас.** Документы рамок и конфиги, которые проект заполняет под себя. | Копируется один раз и дальше живёт своей жизнью |

Механику, которая должна чиниться в одном месте, — в плагин. Содержание — в шаблон.

## Зачем это нужно

Один проверенный факт задаёт всю конструкцию. Сабагент получает в свой контекст:
собственный системный промпт, задачу, **всю иерархию `CLAUDE.md` и `AGENTS.md`**,
git status и предзагруженные скилы.

Он **не получает**: историю разговора, ранее прочитанные файлы, auto memory
ведущей сессии.

> Единственное, что разделяют все агенты проекта, — файловый слой. Договорённость,
> произнесённая в чате, для сабагента не существует. В одноагентной работе это
> неудобство; в мультиагентной — источник расхождений, которые всплывают на мерже.

Отсюда и состав базы: всё, что должно действовать на всех агентов, лежит в файлах,
а то, что обязано держаться всегда, — ещё и в хуках, потому что текст это просьба,
а не гарантия.

## Установка

### 1. Плагин

```bash
/plugin marketplace add simbioz-team/muagba-pro
/plugin install muagba-base@muagba-pro
```

Локально, без публикации:

```bash
/plugin marketplace add /home/rustam/develop/simbioz_team/muagba-pro
/plugin install muagba-base@muagba-pro
```

### 2. Каркас в новый проект

```bash
mkdir my-project && cd my-project && git init
cp -a /path/to/muagba-pro/template/. .
```

`cp -a ... /.` — с точкой, иначе точечные файлы (`.claude/`, `.gitignore`,
`.worktreeinclude`) не скопируются.

### 3. Настройка

```
/muagba-base:setup-project
```

Проводит по этапам Э0–Э11 с гейтом на каждом.

## Что даёт плагин

**Хуки** — то, что работает детерминированно, независимо от контекста агента:

| Событие | Скрипт | Что делает |
|---|---|---|
| `PreToolUse` (Edit/Write) | `protect-paths.sh` | Блокирует правку путей из `.claude/protected-paths.txt`; шаблон с префиксом `+` разрешает создать файл и запрещает изменить созданный |
| `PreToolUse` (Bash) | `guard-bash.sh` | Блокирует `rm -rf /`, force-push, `reset --hard`, `clean -fd`, `chmod 777` |
| `Stop` | `gate-check.sh` | Не даёт закрыть ход, пока `.claude/check.sh` красный |
| `SessionStart` (compact) | `reinject-invariants.sh` | Возвращает `.claude/invariants.md` в контекст после компакции |
| `SubagentStart/Stop` | `log-agent.sh` | Журнал запусков в `.claude/logs/agents.jsonl` |

Все хуки — no-op, если проект не завёл соответствующий файл. Базу можно ставить
на любой проект без подготовки.

**Роли:** `implementer` (одна задача в изолированном дереве), `reviewer`
(свежий взгляд на дифф, ничего не правит), `researcher` (исследование в
отдельном контексте).

**Скилы:** `/muagba-base:setup-project`, `/muagba-base:new-feature`,
`/muagba-base:write-adr`.

**Банк вопросов** — `questions/NN-*.md`, по файлу на этап. То, что конвейер
спрашивает у человека, записано, а не вспоминается на ходу. Вопросы Э2–Э4
собраны из литературы, остальные выведены из задач конвейера; у каждого есть
поле «Плохой ответ», дающее агенту право не принять ответ и назвать, чем он
плох. Устройство — `docs/interview.md`.

## Что даёт шаблон

```
README.md                      для людей; агенты его тоже читают
AGENTS.md                      свод правил (кросс-инструментальный стандарт)
CLAUDE.md                      обёртка с @AGENTS.md + специфика Claude Code
.gitignore                     + агентские записи
.worktreeinclude               что копировать в рабочие деревья
.env.example                   список переменных без значений
.mcp.json                      слот под MCP-серверы проекта
.github/workflows/ci.yml       гоняет тот же check.sh, что и Stop-хук
.claude/settings.json          права, слоты под маркетплейсы и плагины
.claude/protected-paths.txt    что нельзя править
.claude/invariants.md          что возвращать после компакции
.claude/check.sh               гейт завершения хода
.claude/check-frames.py        сканер незаполненных документов рамок
.claude/rules/                 правила, в т.ч. с paths-фронтматтером
.claude/agents/                слот под роли этого проекта
.claude/skills/                слот под скилы этого проекта
docs/constitution.md           принципы + пометка способа исполнения
docs/definition-of-done.md     критерии готовности
docs/tech-stack.md             чем делаем / что запрещено
docs/structure.md              раскладка и её принцип
docs/infrastructure.md         окружения, сервисы, секреты (удалить, если нет)
docs/toolchain.md              какие плагины включены и почему
docs/product/{mission,roadmap,glossary}.md
docs/decisions/                ADR
docs/lessons.md                выученное, ещё не ставшее правилом
docs/INDEX.md                  навигация: счётчики + таблица документов
docs/TAGS.md                   машинный индекс для поиска без чтения
specs/                         артефакты задач: spec / plan / tasks
```

### Реестры документации

`docs/INDEX.md` и `docs/TAGS.md` — точка входа в документацию: навигация для
человека и машинный индекс, по которому агент ищет, не читая документы подряд.
В шаблоне они пустые.

Собираются плагином [docsys](../docsys) — там же семь команд `/doc-*`
и четыре проверки документации. Без него реестры можно вести руками, но тогда
они разойдутся с документами; правило `.claude/rules/20-docs.md` задаёт контракт
метаданных независимо от плагина.

### Проверка заполненности

`.claude/check-frames.py` находит то, что осталось заготовкой: слоты `<...>`,
пустой раздел антицелей в `mission.md`, пустой список запрещённого в
`tech-stack.md`, глоссарий без терминов, принципы конституции без пометки
способа исполнения.

`check.sh` вызывает его в мягком режиме (`--soft`): новый проект не должен
краснеть только из-за пустых заготовок. На этапе Э11, когда рамки дописаны,
`--soft` убирается — и незаполненный слот начинает ронять проверку.

Живёт в шаблоне, а не в плагине: CI запускает `check.sh`, а в CI ни Claude Code,
ни плагина нет.

## Этапы настройки

Двенадцать этапов, 67 проб. Подробно — `docs/pipeline.md` (что и почему),
`docs/gates.md` (чем проверяется), `docs/interview.md` (что спрашивается).

| Блок | | Этап | Ключевая проба |
|---|---|---|---|
| Смысл | Э0 | Каркас и гигиена git | агентские записи в `.gitignore` |
| | Э1 | Точка входа для агентов | свод правил ≤ 200 строк |
| | Э2 | Продуктовая рамка | раздел антицелей непуст |
| | Э3 | Конституция и «готово» | у каждого принципа способ исполнения |
| | Э4 | Стек и структура | список «запрещено тянуть» непуст |
| Проверяемость | Э5 | Рабочая среда | записан рецепт запуска |
| | **Э6** | **Контракт проверки** | **`check.sh` краснеет на сломанном** |
| Принуждение | Э7 | Принудительные рамки | синтетический вызов хука даёт 2 |
| | Э8 | Роли и параллелизм | у проверяющего нет инструментов правки |
| | Э9 | Рабочий цикл | шаблон условия `/goal` записан |
| Замыкание | Э10 | Наблюдаемость и накопление | журнал агентов непуст |
| | Э11 | Холостой прогон | `--soft` убран, задача прошла конвейер |

**Э6 — граница.** Параллельных агентов до неё не запускать: без исполнимой
проверки агент останавливается на «выглядит готово», и верификатором становится
человек, который за несколькими агентами не успевает.

## Сторонние плагины

Слот под них — `extraKnownMarketplaces` и `enabledPlugins` в
`template/.claude/settings.json`. Состав пока не зафиксирован: см.
`docs/toolchain.md`.

## Требования

`bash`, `git`, `python3` (хуки разбирают JSON через него, чтобы не тянуть `jq`).
