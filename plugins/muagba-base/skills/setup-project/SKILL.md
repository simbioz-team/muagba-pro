# Настройка окружения проекта

Аргумент: `$ARGUMENTS` — путь к проекту (по умолчанию текущая директория).

**Если путь указывает не на каталог этой сессии — скажи об этом и
остановись.** Настройка со стороны выглядит работающей, а держится на честном
слове: рабочие деревья сабагентов ответвляются от проекта **сессии**, журнал
агентов пишется туда же, и `isolation: worktree` уведёт исполнителя в чужой
репозиторий. Обкатка это показала: два исполнителя ушли работать в один
общий каталог и разошлись только потому, что задачи не пересекались по
файлам. Правильный порядок — открыть сессию в каталоге проекта и запустить
настройку там.

## Кто что решает

**Пройден ли этап, решаешь не ты, а скрипт.**

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/setup_state.py" --json
```

Он прогоняет 69 проб и возвращает `next_stage` — этап, с которого продолжать.
Состояние нигде не хранится, а выводится из репозитория заново при каждом
запуске. Поэтому настройку можно прервать в любой момент: ничего не
потеряется, и отмечать сделанное не надо.

Никогда не объявляй этап пройденным сам. Кажется, что всё сделано, а проба
красная — значит либо не сделано, либо проба смотрит не туда. Второе — повод
сказать человеку, а не пойти дальше.

## Цикл

1. **Прогон.** `setup_state.py --json`.

2. **Признаки.** `undeclared_traits` непуст — спроси про них **раньше всего
   остального**. Пока признак не объявлен, зависящие от него пробы висят в
   `unknown`, и этапы не закрываются. Вопросы под них помечены в банке полем
   «Даёт признак». Запись: `setup_state.py trait ui=true`.

3. **Конец?** `next_stage` равен `null` — настройка закончена. Скажи это и
   остановись.

4. **Этап.** Открой файл банка по номеру: Э0 → `00-git.md`, Э4 → `04-stack.md`,
   Э11 → `11-dry-run.md`.

   ```
   ${CLAUDE_PLUGIN_ROOT}/questions/NN-*.md   банк базы
   .claude/questions/NN-*.md                 своё у проекта, если есть
   ```

   Списки складываются.

5. **Проведи этап** — интервью плюс то, что делается без вопросов (таблица
   ниже). Смотри на `probes[].fix` из прогона: там написано, чего не хватает.

6. **Перезапусти** `--json`. Этап не закрылся — покажи оставшиеся пробы с их
   `fix` и **не иди дальше**.

После каждого этапа покажи, что получилось, и дождись подтверждения. Несколько
этапов молча подряд не делай: человек должен успевать возражать.

## Как вести интервью

**По одному вопросу за раз.** Список из шести вопросов получает список из шести
отписок.

У каждого вопроса в банке есть поля, и они не украшение:

- **`Спрашивать:`** — условие. `если признак ui` проверяется по `traits` из
  прогона. Условие прозой («если в стеке нет хранилища») разбираешь сам,
  прочитав документ предыдущего этапа. Неприменимый вопрос **не задавай
  вообще** — он сбивает и тратит внимание.
- **`Плохой ответ:`** — то, чем ответ окажется бесполезен. Получил такой —
  **скажи, чем именно он плох, и спроси снова.** Один раз. После второго
  запиши как есть и пометь раздел для `/doc-audit`.
- **`Даёт признак:`** — после ответа выполни `setup_state.py trait <имя>=...`.
- **`Заполняет:`** — куда идёт ответ. Документы рамок заводятся через
  `/doc-new`, а не пустым шаблоном.

**Не заполняй документы за человека.** Пустой раздел честнее выдуманного: он
роняет пробу и останавливает конвейер, а правдоподобно дописанный проходит
и остаётся в проекте навсегда — причём никто не помнит, что его никто не решал.

## Готовые материалы

Вопрос В1.5 — **последний на Э1**, после того как развёрнут `docsys`: раньше
материал некуда положить. Спрашивается, есть ли уже написанное — бриф, ТЗ,
README прошлой версии, расшифровка встречи. Это частый вход в конвейер.

Принесённое кладётся в `docs/sources/<slug>.md` типом `source` с заполненным
`origin` и **больше не меняется**. Каталог защищён как «записывается один раз»:
создать файл можно, переписать нельзя.

Дальше на каждом этапе, **до того как задавать вопрос**, ищи на него ответ в
`docs/sources/`. Три исхода:

| | Что делаешь |
|---|---|
| нашёл | показываешь цитату и куда её кладёшь, просишь подтвердить |
| нашёл частично | показываешь цитату и говоришь, чего в ней не хватает |
| не нашёл | задаёшь вопрос обычным порядком |

В документ идёт только подтверждённое. Документ, заполненный из источника,
перечисляет его в поле `sources` своего frontmatter.

**Раздел, который нечем обосновать из источника, оставляй пустым.** Разбор
чужой прозы — лучшее место, чтобы принять желаемое за написанное.

## Каркас в непустой проект

База ставится и на существующий репозиторий — это заявленное свойство, а не
исключение. В каркасе лежат `CLAUDE.md`, `README.md`, `AGENTS.md` и
`.gitignore`, то есть ровно те имена, которые в живом проекте уже заняты.

Поэтому копирование идёт с `-n`: **ничего существующего не перезаписывается.**
Раньше стояло обычное `cp -a`, и на проекте с уже написанным `CLAUDE.md` этап
Э0 стирал его молча, без вопроса и без копии. Нашла сессия, собиравшаяся
ставить базу на живой репозиторий, — за команду до того, как это случилось.

**Коммит делается до копирования, а не после.** Порядок Э0 — `git init`,
потом каркас: в свежем репозитории коммитов ноль, и затёртый файл не лежит ни
в HEAD, ни в индексе, ни в reflog, ни в stash. Восстанавливать неоткуда.
В репозитории с историей то же самое чинится одним `git checkout --`, а здесь
— ничем, причём «новый каталог» и «непустой каталог» сходятся в худшем
варианте: `git init` этап делает сам шагом раньше. Поэтому: есть в каталоге
хоть что-то — сначала коммит существующего, и только потом копирование. Пустой
каталог коммитить нечем, там шаг пропускается.

После копирования **обязательно**:

1. Покажи, какие файлы каркаса не легли, потому что имя занято. Команда:
   `cp -a -n -v "$(...)/." . ` печатает скопированное; непечатавшееся и есть
   пропущенное, либо сравни списки заранее.
2. Разбери каждое совпадение с человеком **по одному**. Молча оставить своё —
   такая же ошибка, как молча затереть: конвейер дальше опирается на то, что
   в этих файлах есть.

Что обычно требует сведения:

- **`CLAUDE.md`** — самый частый и самый обманчивый случай. Это обычно не две
  версии одного файла, а **два разных документа с одинаковым именем**: у
  проекта там предметная область, инварианты и договорённости, у каркаса —
  тонкая точка входа, которая делает `@AGENTS.md` и объявляет специфику
  Claude Code. Сливать их текстом — получить кашу; выбрать один — потерять
  половину.

  Правильный разбор использует раскладку самой базы и не теряет ничего:

  1. Существующий `CLAUDE.md` целиком становится **`AGENTS.md`** — это и есть
     свод правил, кросс-инструментальный. Имя почти всегда свободно: проекты
     с `AGENTS.md`, но без `CLAUDE.md`, встречаются редко.
  2. `CLAUDE.md` из каркаса встаёт на освободившееся место точкой входа с
     `@AGENTS.md`.
  3. Дальше по конвейеру содержимое расходится по своим местам само:
     доменный словарь — в `docs/product/glossary.md` на Э2, инварианты — в
     `.claude/invariants.md` на Э7. Не тащи это руками на Э0, там ещё не
     решено, что из написанного правило, а что описание.

  Проверят результат `entry.import` (импорт на месте) и `entry.size` (свод
  не разросся). Если `AGENTS.md` у проекта тоже занят — вот тогда сведение
  текстом, и только его.
- **`.gitignore`** — агентские записи **дописываются** к существующему файлу,
  а не заменяют его. Проба `git.ignore` спрашивает git, так что проверится
  фактическое игнорирование, а не наличие строк.
- **`README.md`** — README проекта почти всегда важнее каркасного. Каркасный
  нужен как список разделов, не более.

Если проект непустой, скажи об этом человеку **до** копирования и назови, что
именно совпадёт по именам. Человеку проще ответить заранее, чем разбирать
последствия.

## Что делается без вопросов

| Этап | Действия, которых не спрашивают |
|---|---|
| Э0 | `git init`; **если в каталоге уже что-то есть — коммит до копирования**; каркас — `cp -a -n "$(python3 "${CLAUDE_PLUGIN_ROOT}/scripts/find_template.py")/." .` (**см. ниже про непустой проект**); коммит каркаса |
| Э1 | плагины `muagba-base` и `docsys` в настройки проекта; `/doc-init` с объявленным типом `source`; `/context` показывает свод |
| Э2–Э4 | документы через `/doc-new <тип>` — он ведёт по разделам; реестры пересобирает `rebuild_registries.py` |
| Э5 | рецепт запуска — `.claude/skills/run-<имя>/SKILL.md`. Не сочинять: подними приложение **с чистого окружения** и запиши то, что действительно сработало. Дальше по нему пойдёт `/run` и любой агент |
| Э6 | собрать `.claude/check.sh` из решённых уровней; CI завести на **ту же** команду |
| Э7 | написать хуки под принципы с пометкой «машинно»; прогнать самотест запретов |
| Э8 | роли приходят с плагином; проектные — в `.claude/agents/` |
| Э9 | подтверждение на живом приложении идёт по рецепту из Э5, а не по тестам: зелёные тесты не значат, что фича работает |
| Э10 | журнал агентов пишет плагин, заводить нечего |
| Э11 | провести задачу через весь путь; снять `--soft`; **раскомментировать строки документов рамок** в `.claude/protected-paths.txt`; зафиксировать коммитом |

**Э6 — граница. Параллельных агентов до неё не запускать.** Без исполнимой
проверки агент останавливается на «выглядит готово», и верификатором
становится человек, который за несколькими агентами не успевает.

## Человеческие гейты

Двенадцать проб машина закрыть не может. Три из них — про смысл
(`product.audit`, `const.audit`, `stack.audit`): человек читает документ
целиком и говорит, что это его текст, а не конспект чужого. Остальные — про
факт, случившийся в мире: приложение поднялось, проверка покраснела, два
агента не столкнулись.

Такую пробу **ты не подтверждаешь**. Ты говоришь, что нужно сделать, и даёшь
команду:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/setup_state.py" confirm <id> --note "что именно наблюдали"
```

Подтверждение протухает: если файл, о котором свидетельствовали, изменился,
проба снова краснеет.

## Чего не делать

- Не заполнять документы за человека, чтобы «было».
- Не ставить сторонние плагины по ходу настройки. Класс А (`muagba-base`,
  `docsys`) ставится молча на Э1, остальное — отдельным разговором и по
  триггеру, иначе описания скилов забьют контекст без пользы.
- Не пропускать Э6.
- Не редактировать `docs/sources/`. Исправления идут в документы рамок.
- Не считать `skip` достижением: он значит «неприменимо», а не «сделано».
