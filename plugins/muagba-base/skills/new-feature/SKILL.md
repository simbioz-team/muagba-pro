# Новая фича

Аргумент: `$ARGUMENTS` — короткое описание фичи.

Создай `specs/<NNN>-<slug>/`, где `NNN` — следующий свободный номер.

## 1. spec.md — что и зачем

Сначала **интервью**, а не сразу текст. Задавай вопросы через `AskUserQuestion`,
копай в края и компромиссы, не спрашивай очевидного. Продолжай, пока не закроются
все дыры.

Содержание: задача и зачем она; сценарии использования; требования в проверяемой
форме (`КОГДА <условие> СИСТЕМА ДОЛЖНА <поведение>`); **что вне рамок**; критерии
приёмки.

Всё, что осталось неясным, помечай `[ТРЕБУЕТ УТОЧНЕНИЯ: вопрос]` и не заметай
под ковёр.

**Не переходи к плану, пока в файле остались такие пометки.**

## 2. plan.md — как

Файлы и интерфейсы, которые затрагиваются. Порядок изменений. Риски.

Обязательная секция **«Сверка с конституцией»**: перечисли принципы из
`docs/constitution.md` и отметь каждый — соблюдён либо нарушен с обоснованием.
Нарушение без обоснования — стоп.

## 3. tasks.md — нарезка

Задачи по 2–5 минут работы каждая. Формат строки:

```
- [ ] T001 <действие> → <проверяемый результат>   [P]
```

`[P]` — задачу можно делать параллельно с соседними (не пересекается по файлам).
Задача без проверяемого результата — не задача.

У каждой задачи обязателен список файлов, которые она трогает: по нему
определяется пересечение, и без него задачу нельзя брать в параллель.

**Этот файл — нарезка фичи, а не доска.** Состояние «взято, кем, что
осталось» в нём жить не может: исполнители работают в отдельных рабочих
деревьях, у каждого свой checkout, и отметка «взял» до соседа не доезжает —
незакоммиченная не попадает в чужое дерево вовсе, закоммиченная остаётся в
своей ветке. Это нашли три прогона обкатки независимо друг от друга.

Где живёт общее состояние, проект объявляет на Э8 и записывает в
`docs/workflow.md`, раздел «Где живут задачи» (`ADR-0008`). Оттуда его и
берут, а `tasks.md` остаётся описанием работы.

## 4. Раздача

По правилам проекта из `docs/workflow.md` — кто раздаёт, кто ревьюит, что
обязано быть зелёным. Задачи с `[P]` уходят параллельным `implementer`-агентам
в отдельных деревьях, затем `reviewer` на общий дифф.

**Параллельная раздача возможна только если проект объявил, где живёт общее
состояние задач,** и это место вне рабочего дерева. Не объявил — фичи делаются
по одной, и это честный режим, а не поражение: пересечение по файлам у многих
продуктов норма, а не исключение.
