# ADR-0007. Не писать своё, если есть живое чужое

- **Дата:** 2026-09-20
- **Статус:** принято

## Контекст

База уже несёт двенадцать этапов, банк вопросов, пять хуков и семьдесят проб.
Каждая своя подсистема — ещё один кусок, который чиним мы и никто больше.

Второй круг обкатки показал цену наглядно. Координация параллельных агентов
через `tasks.md` не работает: у каждого рабочего дерева свой checkout,
незакоммиченная доска в дерево не попадает, закоммиченная остаётся в ветке
того, кто отметился. Дефект нашли все три прогона **независимо друг от друга**,
а внутри прогонов — ещё и их сабагенты.

Разведка после этого заняла двадцать минут и показала, что задача давно решена
дважды: в самом Claude Code (общий список задач с захватом через файловую
блокировку, зависимости, почта между агентами) и у сообщества (`ccpm` — доска
в GitHub Issues, эпики в отдельных рабочих деревьях). Оба решения устроены
одинаково в главном: **общее состояние вынесено туда, куда рабочее дерево не
дотягивается**. Мы же держали его в репозитории — то есть ровно в том месте,
которое worktree и разрезает.

Двадцать минут разведки сэкономили бы подсистему, которую мы написали и
которая не работает.

## Решение

Перед тем как проектировать подсистему, проводится разведка в три шага:

1. Что есть **встроенного** в Claude Code.
2. Что есть в **официальном маркетплейсе**.
3. Что есть **у сообщества** и признано.

Своё пишем, только если готовое не подошло, и причина записывается — здесь или
в следующем ADR. Ненайденное готовое — тоже результат разведки, и он тоже
записывается, иначе через месяц мы начнём искать заново.

### Что значит «живое чужое»

Без критерия «признано сообществом» означает «понравилось». Критерий:

| | |
|---|---|
| Развивается | коммиты за последние месяцы, а не архив |
| Используется не только автором | форки, обсуждения, чужие отчёты о применении |
| Лицензия позволяет | и совместима с нашей |
| Граница ответственности понятна | что именно сломается, если проект умрёт |
| Цена входа измерима | токены, хуки, конфликты — по `ADR-0002` |

### Чем это не является

Заимствованное **не становится классом А автоматически**. Главное свойство
базы — ставиться на любой проект без подготовки, поэтому нельзя требовать
того, что выключено по умолчанию, помечено экспериментальным или тянет за
собой чужой хостинг.

Поэтому конвейер спрашивает, **чем пользуемся**, записывает выбор в
`docs/toolchain.md` с условием снятия, а проба проверяет **свойство, а не
инструмент**. Свойство переживает смену инструмента, проба на конкретный
плагин — нет.

## Альтернативы

**Писать своё всегда.** Отклонено. Цена сопровождения растёт с каждой
подсистемой, а обкатка показала, что своё ломается ровно там, где чужое давно
отлажено: на границах, которые вживую проходили тысячи людей, а мы — трое
агентов за одну ночь.

**Брать чужое всегда.** Отклонено. Плагин исполняется с правами пользователя
(`ADR-0002`), а зависимость от чужого темпа развития иногда дороже своего кода.
Решение принимается каждый раз, а не один раз навсегда.

**Не решать, выбирать по случаю.** Отклонено. Именно так мы и написали
`tasks.md`: никто не решал писать своё — просто не посмотрели, есть ли готовое.

## Последствия

**Проще:** подсистем меньше, и каждая следующая начинается с вопроса «а есть ли
уже?», а не с проектирования.

**Сложнее:** разведка становится обязательным шагом и стоит времени. Её
результат надо записывать, включая отрицательный.

**Теперь нельзя:** проектировать подсистему, не показав, почему готовое не
подошло. И нельзя ссылаться на «признано сообществом», не приложив к этому
пять пунктов критерия.

Первое применение — `ADR-0008`: задачи переезжают из рабочего дерева наружу.
