# ADR-0008. Задачи живут вне рабочего дерева

- **Дата:** 2026-09-20
- **Статус:** принято

## Контекст

`tasks.md` в репозитории был объявлен единственным каналом координации
параллельных агентов. Он им не является, и это выяснилось тремя независимыми
путями сразу.

**Не доезжает.** У каждого рабочего дерева свой checkout. Незакоммиченная доска
в дерево не попадает вовсе; закоммиченная попадает, но отметка «задача взята»
остаётся в ветке того, кто её поставил, и соседний агент её не видит. То есть
файл разрезается ровно тем механизмом изоляции, ради которого он и нужен.

**Писать некому.** Файл не входит в «Трогает» ни одной задачи, а исполнителю
запрещено править файлы вне своей задачи. Канал координации, в который по
правилам нельзя писать.

**Проба смотрит не туда.** `roles.board` проверяет доску в основном дереве —
там, где агентов нет.

Разведка по `ADR-0007` показала: оба готовых решения — встроенный общий список
задач Claude Code и `ccpm` — устроены одинаково в главном. Состояние задач
вынесено туда, куда рабочее дерево не дотягивается: в каталог сессии или в
GitHub Issues. Мы держали его в единственном месте, которое worktree разрезает.

## Решение

**Состояние задач не хранится в рабочем дереве.** Файл задач — представление,
а не источник истины.

Источником истины может быть:

- **встроенный общий список** Claude Code — состояние в каталоге сессии,
  захват задачи через файловую блокировку, зависимости, события
  `TaskCreated` / `TaskCompleted` / `TeammateIdle` как готовые точки для гейтов;
- **MCP-сервер управления задачами** — `github`, `linear`, `atlassian`,
  `asana`, `gitlab` и прочие есть в официальном маркетплейсе;
- **GitHub Issues** через `ccpm`, если команда и так живёт в issues.

### Работа с MCP-сервером задач закладывается сразу

Не дописывается потом. Если задачи ведутся во внешнем трекере, это не
надстройка над файлом, а способ хранения, и он выбирается тогда же, когда
выбирается всё остальное в среде:

1. **Э5** — сервер объявляется в `.mcp.json` вместе с остальными MCP, по тем же
   правилам и с теми же вопросами про доступы и секреты.
2. **Э8** — вопрос «где живут задачи» задаётся до того, как заводится первый
   параллельный агент, и выбор записывается в `docs/toolchain.md` с условием
   снятия.
3. **Проба** проверяет, что сервер объявлен и отвечает, а не что он упомянут.

Причина, по которой это решается сразу: задачи — единственное общее состояние
между агентами. Механизм, выбранный после того, как агенты уже работают,
придётся внедрять в работающий процесс, а не в пустой проект.

### `tasks.md` остаётся, но честным

Для однопоточной работы файл в репозитории — нормальный и самый дешёвый
вариант. В самом файле теперь написано, что он именно такой, и что при переходе
к параллельным агентам состояние переезжает наружу.

### Это не отменяет `ADR-0003`

Речь о разных задачах, и их легко спутать. `ADR-0003` — про 53 задачи **самого
конвейера настройки**: графа из них мы не строим, порядок линеен, зависимости
выводятся из гейтов. Здесь — про **рабочие задачи проекта**, которые разбирают
между собой параллельные агенты уже после настройки. Первые живут в документах
базы, вторые — в трекере, и строить граф из вторых мы по-прежнему не
собираемся: зависимости, если они есть, ведёт тот инструмент, который выбран.

### Проба проверяет свойство, а не инструмент

Правило: **если агенты работают в отдельных рабочих деревьях, общее состояние
задач не лежит в рабочем дереве.** Оно переживёт и смену трекера, и уход любого
из перечисленных инструментов; проба на конкретный плагин — нет.

## Альтернативы

**Починить `tasks.md`: коммитить доску, завести блокировки в файле.** Отклонено.
Это воспроизведение git-локов поверх git, причём без атомарности, которую даёт
файловая блокировка в одном каталоге. И главный вопрос — кто имеет право писать
в общий файл — остаётся открытым.

**Требовать встроенный общий список.** Отклонено. Он экспериментальный,
выключен по умолчанию, не восстанавливается при возобновлении сессии, и
вложенных команд в нём нет — а Э8 предполагает, что исполнитель может позвать
своих. База обязана ставиться на любой проект без подготовки, поэтому требовать
его нельзя. Предлагать — можно и нужно.

**Требовать GitHub Issues.** Отклонено. Привязывает проект к хостингу и требует
`gh` с авторизацией. Для проекта без GitHub конвейер перестал бы работать.

## Последствия

**Проще:** рабочие деревья перестают ломать координацию — разрезать больше
нечего. Гейты получают готовые точки подключения вместо самодельных.

**Сложнее:** появляется внешняя зависимость, и на неё нужен ответ «а если
недоступна». Ответ: однопоточный режим с файлом, и он должен работать всегда.

**Теперь нельзя:** объявлять файл в репозитории каналом координации параллельных
агентов. И нельзя закрывать Э8, не ответив, где живут задачи.

Закрывает дефекты круга 2: `tasks.md` не координирует (найден всеми тремя
прогонами) и `roles.board` смотрит в основное дерево.
