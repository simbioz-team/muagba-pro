# ADR-0012. Журнал сессии переживает сжатие контекста — своё, на встроенных хуках

- **Дата:** 2026-09-24
- **Статус:** принято

## Контекст

На длинных ночных прогонах контекст сжимается несколько раз. При сжатии
теряется то, чего нет в коде: где работа сворачивала не туда, что решили и
почему, что открыто. Нужен механизм, при котором агент заранее записывает
журнал сессии, а после сжатия перечитывает его и продолжает.

По рамкам `ADR-0009` это наше: правило не про то, как строить, а про то, как
агент отказывает, — теряет сделанное при сжатии. База уже возвращает
`.claude/invariants.md` после компакции; журнал — продолжение той же заботы.

## Что умеет Claude Code

Проверено по документации хуков и по самой программе (2.1.280):

- **Агент не может сам вызвать `/compact`.** Ни инструмента, ни способа из
  хука. Сжимает Claude Code, когда контекст подходит к окну автосжатия.
- **`PreCompact`** запускается перед сжатием и умеет его запретить. Но если
  сжатие запущено уже после ошибки переполнения от API, запрет роняет
  запрос. Для ночного прогона это остановка.
- **`PostCompact`** получает `compact_summary` — выжимку, которую сделал сам
  Claude Code. Решений не принимает, годится для побочных действий.
- **`SessionStart` с `compact`** — его stdout попадает в контекст агента.
- **Заполненность контекста хуку не передаётся.** Её считают по `usage`
  последнего ответа в `transcript_path`. Размер окна не передаётся тоже и
  зависит от модели и настроек: 200K, ~967K, `autoCompactWindow`,
  `CLAUDE_CODE_AUTO_COMPACT_WINDOW`.

Справочный агент по документации утверждал, что `PreCompact` и `PostCompact`
не существуют. Опровергнуто по бинарнику и по странице хуков — пример того,
почему вывод об устройстве чужого инструмента проверяется по инструменту.

## Разведка по `ADR-0007`

Официальный маркетплейс: плагина про сжатие контекста нет.

| Кандидат | Почему не берём |
|---|---|
| Continuous-Claude-v3 (3.9k★) | Docker, PostgreSQL+pgvector, TypeScript; не обновлялся с января 2026 |
| claude-mem (94k★) | Bun, воркер с HTTP API, облачная синхронизация; хука `PreCompact` нет |
| cc-sessions (1.5k★) | Свой процесс работы и инсталлятор; окно зашито в код как 160 000 |
| claude-remember | Лицензия запрещает коммерческое распространение |
| anti-compact | node ≥ 22.5, beads; 1★ |
| claude-code-context-handoff | По устройству ровно наше, python3 + bash, MIT — но 2★ и `"author": "Your Name"`: не проходит «используется не только автором» |

## Решение

Своё, три хука на одном модуле `journal_watch.py`:

1. **`PostToolUse`** — контекст вырос на `MUAGBA_JOURNAL_EVERY` токенов
   (150 000) с последней записи журнала — напомнить агенту обновить его.
   Проигнорированное напоминание повторяется раз в четверть порога, не чаще.
2. **`PostCompact`** — сохранить `compact_summary` в `docs/journal/raw/`.
3. **`SessionStart` (compact)** — назвать последнюю запись и велеть
   перечитать её, сверить с выжимкой и продолжить со следующего шага.

Включается каталогом `docs/journal/`; нет каталога — молчит.

**Порог — рост, а не процент окна.** Окно хуку не передаётся, и угаданное по
модели промахивалось бы молча — как у cc-sessions с зашитыми 160 000. Рост от
последней записи окна знать не требует и одинаково работает на 200K и 1M.

**`PreCompact` не используем.** Запрет сжатия ради журнала рискует обрушить
ночной прогон; `PostCompact` даёт ту же страховку без риска.

**Состояние — в `scratchpad_dir` сессии, не в репозитории:** в чужом проекте
`.claude/logs/` может не стоять в `.gitignore`.

## Последствия

- Журнал ведёт агент, хук только напоминает. Напоминание можно
  проигнорировать; страховка на этот случай — выжимка в `raw/`.
- `transcript` пишется асинхронно и может отставать на ход — для порога в
  сотню тысяч токенов это неважно.
- Если Claude Code начнёт передавать заполненность контекста в хук, порог
  стоит пересмотреть; если появится признанный плагин того же устройства —
  снять своё по `ADR-0007`.
