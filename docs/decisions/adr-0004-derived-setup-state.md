# ADR-0004. Состояние настройки выводится, а не хранится

- **Дата:** 2026-09-20
- **Статус:** принято

## Контекст

Конвейер настройки должен прерываться в любой момент и продолжаться с места
остановки. Значит нужно знать, какие этапы пройдены.

Очевидный способ — вести журнал: отметил этап сделанным, при следующем запуске
прочитал. Способ плохой ровно тем же, чем плохи реестры документации, которые
ведёт агент: журнал начинает расходиться с репозиторием. Кто-то удалил
`check.sh`, а галочка на этапе стоит — и конвейер уверенно идёт дальше по
несуществующему основанию.

## Решение

Состояние выводится из репозитория при каждом запуске. `setup_state.py`
прогоняет пробы и называет первый незакрытый этап.

Хранится только то, что из репозитория не выводится:

- **признаки проекта** — есть ли UI, хранилище, удалённый репозиторий; их
  объявляет человек, потому что догадка по коду может молча пропустить нужный
  гейт;
- **человеческие подтверждения** — девять фактов, случившихся в мире:
  приложение поднялось, проверка покраснела, два агента не столкнулись.

Правило закрытия: `все машинные пробы зелёные И человеческие подтверждены`.
Машинные пересчитываются всегда, поэтому подтверждение само по себе этап не
закрывает.

Подтверждения протухают: человеческая проба объявляет файлы, от которых
зависит её утверждение, и при подтверждении сохраняется их отпечаток. Файл
изменился — подтверждение недействительно.

## Альтернативы

**Журнал пройденных этапов.** Отклонено: расходится с репозиторием, и
расхождение не видно.

**Журнал + периодическая сверка.** Отклонено: сверка — это и есть прогон проб.
Если пробы всё равно нужны, журнал становится кэшем, который может только
врать.

**Трекер задач вместо проб.** Отклонено по той же причине плюс внешняя
зависимость.

**Автоопределение признаков проекта** вместо объявления человеком. Отклонено:
неверная догадка пропускает гейт молча. Если у проекта есть интерфейс, а
скрипт решил, что нет, браузерные пробы не выполнятся и никто не заметит.

## Последствия

Проще: прерывание настройки не требует ничего. Состояние не может соврать.
Удалённый артефакт немедленно открывает свой этап обратно.

Сложнее: каждая проба должна быть дешёвой, иначе проверку перестанут
запускать. Это ограничение сформировало почти весь состав проб — вместо
дорогого действия проверяется дешёвый след, который оно оставило.

Теперь нельзя: закрыть этап, не оставив в репозитории следа. Проба, которую
нечем проверить, должна стать человеческой — с отпечатком, чтобы протухала.
