# ADR-0002. Два класса плагинов

- **Дата:** 2026-09-19
- **Статус:** принято

## Контекст

Возникла путаница: с одной стороны, плагин исполняется с правами пользователя
и его хуки могут блокировать действия — ставить без решения нельзя. С другой,
спрашивать разрешения на каждый шаг конвейера — шум, а конвейер без своих
инструментов не работает вовсе.

Обсуждение буксовало, пока не выяснилось, что речь о двух разных вещах.

## Решение

Два класса, различаются не составом, а тем, кто и когда решает.

**Класс А — инструмент конвейера.** Критерий строгий: *без него гейт этапа не
закрывается*. Ставится молча, состав не обсуждается, записан в самом этапе.
Сегодня это `muagba-base` и `docsys`.

**Класс Б — обвязка проекта.** Выбирает человек. Единица выбора — проект, не
задача: плагины включаются в настройках проекта и требуют перезапуска сессии.
Момент — по триггеру, а не авансом. У каждого записано условие снятия.

## Альтернативы

**Один класс, всё спрашивать.** Отклонено: конвейер не может работать, если
каждый его шаг требует подтверждения установки собственного инструмента.

**Один класс, ничего не спрашивать.** Отклонено: плагин — исполняемый код с
правами пользователя.

**Выбирать под задачу, а не под проект.** Отклонено по техническим причинам:
`/plugin install` требует перезапуска сессии, переключать состав под каждую
задачу невозможно.

## Последствия

Проще: конвейер ставит своё сам; человек решает только там, где решение
осмысленно.

Сложнее: критерий класса А надо применять строго, иначе в него начнёт попадать
всё удобное. Проверка простая — можно ли закрыть гейт без плагина.

Теперь нельзя: добавить плагин в класс А, не сделав его необходимым для гейта.
Предложить плагин класса Б без цены в токенах, списка хуков, конфликтов и
условия снятия.
