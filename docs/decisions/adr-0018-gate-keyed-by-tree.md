# ADR-0018. Гейт хода помнит проверенное содержимое, а не коммит

- **Дата:** 2026-10-20
- **Статус:** принято

## Контекст

Замер narta по спеке 022 (`docs/journal/2026-10-20-022-checks.md` в narta):
из прогонов гейта на критическом пути большая часть проверяла уже
проверенное.

- Отпечаток включал HEAD. Коммит без правок давал новое «дерево», и гейт
  гонял полный набор заново: 22 повторных прогона, около 105 минут.
- Отпечаток жил в одном рабочем дереве. ff-слияние приносило координатору
  ровно то, что гейт исполнителя только что проверил зелёным, и проверка
  шла снова.
- Проверка не знала, что изменилось, и не могла сузить набор: правка
  одной спеки гоняла UI-тесты.
- Исполнитель, остановившийся ждать свой фоновый прогон, получал гейт на
  полпути, а через минуту — ещё один.
- В журнале был только `block`. Зелёные прогоны и их длительность
  приходилось восстанавливать по косвенным признакам.

## Решение

1. **Отпечаток — хеш дерева git рабочих файлов** (`git write-tree` во
   временной копии индекса; отслеживаемые с правками и неотслеживаемые,
   кроме игнорируемых и `.claude/logs`). HEAD в отпечаток не входит.
2. **Список зелёных общий для всех рабочих деревьев** — в
   git-common-dir, `muagba-gate-green`: «дерево событие время». Сабагенту
   засчитывается только зелёный SubagentStop, основной сессии — и Stop, и
   SubagentStop. Набор на Stop по правилу каркаса не шире набора
   SubagentStop.
3. **Проверке передаётся, что изменилось:** `MUAGBA_GATE_BASE` — последнее
   зелёное дерево этого рабочего дерева (для его события),
   `MUAGBA_GATE_CHANGED` — файл со списком путей. Нет базы — переменных
   нет, и проверка берёт полный набор. Каркасный `check.sh` по ним
   выбирает короткий набор (`check-docs`, если проект завёл такую цель,
   иначе `check-quick`).
4. **Остановка с живым своим фоновым прогоном откладывает гейт**
   (`decision=deferred`). Источник — `background_tasks` из входа хука
   (Claude Code ≥ 2.1.3xx, снято с живого входа 2.1.304). Там задачи всей
   сессии: `subagent` и `shell`, на Stop — и shell, оставленные
   сабагентами. В счёт — только `shell` с номером в своей стенограмме:
   `transcript_path` на Stop, `agent_transcript_path` на SubagentStop.
   Задача старше `MUAGBA_GATE_DEFER_MAX_S` (по умолчанию — отсечка гейта)
   не в счёт: прогон короче отсечки, а dev-сервер живёт бесконечно.
   `MUAGBA_GATE_ALWAYS=1` отключает отсрочку.
4а. **Новое дерево без своего зелёного** берёт базой отпечаток HEAD (по
   тем же правилам, что ключ), если тот зелёный для события.
5. **В журнал пишется каждое решение:** `pass`, `block`, `timeout`,
   `released_on_question` — с `duration_ms`; `cached` и `deferred`.

## Последствия

- Возврат к дереву, бывшему зелёным, после красного прогона — кэш. Раньше
  красный стирал отпечаток. Проверка детерминирована по содержимому, а
  нестабильный тест так прячется не лучше и не хуже, чем раньше.
- Чего нет в дереве, гейт не видит: базу данных, окружение, файлы из
  `.gitignore`. Так было и до решения.
- Новые и изменённые файлы ложатся в базу объектов git без ссылок, и их
  убирает обычный `git gc`.
- Бесконечная фоновая задача моложе предела на последней остановке
  исполнителя — сдача без гейта. Дерево исполнителя тогда не в списке
  зелёных, и после слияния его проверит Stop координатора. Нужно строже —
  `MUAGBA_GATE_DEFER_MAX_S` меньше или `MUAGBA_GATE_ALWAYS=1`.
- Содержимое новых и изменённых файлов на каждом прогоне ложится в
  `.git/objects` рыхлыми объектами без ссылок; их снимает `git gc`.

## Отвергнуто

- **Отпечаток по HEAD + `git status`** — то, от чего уходим: коммит без
  правок считается новым деревом.
- **Хеш файлов своим обходом.** Повторяет то, что git делает быстрее и с
  учётом `.gitignore`.
- **Своя классификация путей в базе** (какие правки «только документы»).
  Это решение проекта; база передаёт список путей, а набор выбирает
  `check.sh` проекта.
