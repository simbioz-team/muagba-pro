# Сторонние плагины базы

**Статус: состав не зафиксирован.** Каркас готов, выбор плагинов — отдельный
разговор. Этот файл — место, где решение будет записано вместе с причиной.

Плагины ставятся в **окружение**, а не в репозиторий. Проект объявляет их через
`extraKnownMarketplaces` и `enabledPlugins` в `.claude/settings.json` — тогда
они подхватываются у всех, кто доверил папку, без отдельных запросов.

```json
{
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": { "source": "github", "repo": "anthropics/claude-plugins-official" }
    }
  },
  "enabledPlugins": {
    "muagba-base@muagba-pro": true
  }
}
```

## Правило отбора

Каждый плагин грузит описания своих скилов в контекст **каждой** сессии. Десять
плагинов «на всякий случай» — это шум, из-за которого перестают срабатывать
нужные скилы. Ставить только под доказанный триггер.

Триггеры из официальной документации:

| Триггер | Что добавлять |
|---|---|
| Агент ошибся в соглашении дважды | строка в `AGENTS.md` |
| Тот же промпт в третий раз | скил |
| Тот же плейбук вставляется в чат | скил |
| «Каждый раз без исключений» | хук |
| Побочная задача забивает контекст выводом | сабагент |
| Второму репозиторию нужна та же обвязка | плагин |

## Кандидаты

Проверено в официальном каталоге Anthropic (`anthropics/claude-plugins-official`,
310 плагинов на момент проверки).

| Плагин | Что даёт | Решение |
|---|---|---|
| `superpowers` | Методология: brainstorming, writing-plans, TDD, subagent-driven-development, using-git-worktrees | ? |
| `claude-code-setup` | Аудит обвязки по существующему коду; только рекомендует, файлов не пишет | ? |
| `claude-md-management` | Аудит качества `CLAUDE.md`, захват выученного за сессию | ? |
| `hookify` | Превращает замеченный паттерн в хук | ? |
| `code-review` | Ревью диффа несколькими агентами | ? |
| `security-guidance` | Предупреждения на правках, LLM-ревью диффа на Stop | ? |
| `<язык>-lsp` | Code intelligence: навигация по символам, живые ошибки типов | ? |
| `commit-commands` | Единообразные коммиты и PR | ? |

Пересечения, которые надо развести до установки:

- `superpowers` и spec-driven-конвейер (`new-feature`) оба дают планирование.
  Два конвейера одновременно — агент будет метаться между ними.
- `code-review` и встроенный `/code-review` перекрываются.
- `security-guidance` вешает свой Stop-хук рядом с `gate-check.sh` базы.
  Хуки складываются, не перекрываются — оба будут выполняться.
