# Плагины

Два класса, и путать их не надо: они различаются не составом, а тем, **кто и
когда решает**.

| | Класс А — инструмент конвейера | Класс Б — обвязка проекта |
|---|---|---|
| Критерий | без него гейт этапа не закрывается | помогает работать, но гейт закроется и без него |
| Кто решает | никто, это часть машинерии | человек |
| Когда | на своём этапе, молча | по триггеру, когда нужда доказана |
| Где записан | в самом этапе конвейера | здесь, с причиной и условием снятия |

Разделение нужно потому, что спрашивать разрешения на каждый шаг конвейера —
шум, а ставить что попало без разрешения — риск: плагин исполняется с вашими
правами, а его хуки могут блокировать ваши действия.

Почему именно так — `ADR-0002`.

Перед тем как писать своё, смотрим, есть ли готовое: встроенное в Claude Code,
в официальном маркетплейсе, у сообщества. Порядок разведки и критерий «живое
чужое» — `ADR-0007`. Первое применение — `ADR-0008`: задачи переехали из
рабочего дерева наружу.

## Класс А: инструмент конвейера

Ставится задачей З1.5, состав не обсуждается.

| Плагин | Без него не закрывается |
|---|---|
| `muagba-base` | весь конвейер: хуки, гейты, роли, сам `/setup-project` |
| `docsys` | Э2–Э4: документы рамок — документы системы документации (`ADR-0001`) |

С 0.10.1 это не просьба к человеку, а объявленная зависимость: `docsys`
записан в `dependencies` манифеста `muagba-base`, и Claude Code ставит его
сам. Класс А тем самым выражен механикой, а не абзацем в README — критерий
«без него не закрывается гейт» и «плагин не установится без него» совпали.

Зависимость межмаркетплейсная, поэтому в `marketplace.json` базы стоит
`allowCrossMarketplaceDependenciesOn: ["docsys"]`. Без этого поля Claude Code
отказывается тянуть плагин из каталога, который пользователь не
просматривал, — и это правильная осторожность, а не препятствие.

Проверка критерия — вещь строгая. `claude-md-management` полезен на Э1, но гейт
Э1 («файлы есть, ≤200 строк, импорт на месте») закрывается без него. Значит
класс Б. `hookify` удобен на Э7, но хуки пишутся и руками. Класс Б.

## Класс Б: обвязка проекта

### Правило выбора

1. **Единица выбора — проект, не задача.** Плагины включаются в настройках
   проекта и требуют перезапуска сессии. «Подключить под задачу» технически
   невозможно.
2. **Момент — по триггеру, а не авансом.** Ставим, когда нужда проявилась, а
   не когда кажется, что пригодится. Обоснование придумать легко, и «осознанно
   выбранное заранее» — то же самое «на всякий случай», только с оправданием.
3. **Решает человек.** Агент предлагает.
4. **У каждого записано условие снятия.** Без него решение необратимо на
   практике, даже если обратимо технически.

### Что должно быть в предложении

Не «зачем», а пять пунктов — иначе решать не из чего:

| | |
|---|---|
| Зачем | какой триггер закрывает |
| Цена | токены в каждой сессии, из `claude plugin details` |
| Хуки | какие события вешает; **хуки складываются, а не заменяют** |
| Конфликты | с чем перекрывается из уже стоящего |
| Когда снимать | признак, по которому станет ясно, что не нужен |

### Триггеры

Из официальной документации, проверено:

| Триггер | Что добавлять |
|---|---|
| агент ошибся в соглашении дважды | строка в своде правил |
| тот же промпт в третий раз | скил |
| тот же плейбук вставляется в чат | скил |
| «каждый раз без исключений» | хук |
| побочная задача забивает контекст выводом | сабагент |
| второму репозиторию нужна та же обвязка | плагин |

### Ревизия

На Э10, вместе с разбором накопленного: что из поставленного ни разу не
пригодилось — снять. Без обратного хода набор только растёт, и через полгода
из десяти плагинов работают три, а описания скилов грузятся у всех десяти.

Дело не в токенах — у `muagba-base` их 421. Дело в шуме: когда описаний много
и они похожи, агент берёт не тот скил или не берёт нужный.
