# impeccable: дизайн-плагин и граница базы

- **Дата:** 2026-09-26
- **Статус:** разбор сделан, решение отложено до пилота. Пилот ждёт
  проекта с настоящим интерфейсом.
- **Повод:** вопрос владельца — добавить https://impeccable.style/ для
  работы с фронтендом и дизайном; куда именно и часть ли это muagba-pro.

Записка живёт, пока из неё не вырастет ADR. Факты ниже сняты с репозитория
`pbakaus/impeccable` (коммит `9d715cc`, 2026-09-24), а не с сайта.

## 1. Что это

Плагин и CLI против «AI slop» — шаблонных решений, к которым агенты
тянутся в интерфейсах. Для Claude Code — свой маркетплейс
(`/plugin marketplace add pbakaus/impeccable`): один скил, 24 команды
(`/impeccable init`, `polish`, `audit`, `critique`, `live`, …), 61 проверка
на анти-паттерны.

| Критерий `ADR-0007` | Факт |
|---|---|
| Развивается | коммиты ежедневно, версия 4.4.0 |
| Используется не только автором | 71 тыс. звёзд, 4,3 тыс. форков |
| Лицензия | Apache-2.0 |
| Граница ответственности | дизайн интерфейса: визуальная система, типографика, полировка |
| Цена входа | хуки на `SessionStart`, `PostToolUse` (`Edit\|Write`), `Stop` (до 30 с); бинарник, скачиваемый `curl` при первом запуске; файлы `PRODUCT.md`, `DESIGN.md`, `.impeccable/` |

Разведку проходит.

## 2. Часть ли это базы — нет

По трём вопросам рамок (`ADR-0009`):

1. **Сколько раз выполняется.** Почти всё — на каждой правке интерфейса:
   хуки на каждом `Edit`/`Write` и `Stop`, команды на каждую фичу. Один
   раз — только `init`. Значит, чужое.
2. **Что мерить базе.** Не «стоит ли impeccable», а свойство: у проекта с
   интерфейсом записано, где его визуальная система и чем проверяется
   качество интерфейса.
3. **Как строить или как отказывает агент.** Он лечит настоящий отказ —
   агент тянется к шаблонному, — но средство — словарь и методология
   дизайна, то есть «как строить».

Итог: **чужой инструмент класса Б**, как Spec Kit и docsys. База его не
встраивает, а подключает проектам с признаком `ui` через вопрос конвейера и
запись в `docs/toolchain.md` с условием снятия. Проба, если будет, — на
свойство, а не на impeccable.

Альтернатива, которую сравнивать обязательно: `frontend-design` из
официального маркетплейса Anthropic.

## 3. Главный риск — второй источник продуктовой правды

Разобрано по исходникам (`crates/context/src/context.rs`).

impeccable ищет `PRODUCT.md` и `DESIGN.md` **только под этими именами**
(допускаются `Product.md`, `product.md`) и **в таком порядке**:

1. корень проекта;
2. `.agents/context/`;
3. `docs/`;
4. каталог из `IMPECCABLE_CONTEXT_DIR` — только если на шагах 1–3 не
   найдено ни одного из двух файлов.

Наш `docs/product/mission.md` он не видит. Без подготовки `/impeccable
init` проведёт своё интервью и напишет `PRODUCT.md` в корень — второй
документ о том же, который разойдётся с первым. Это ошибка, которую уже
разбирали со Spec Kit.

Пересечение разделов:

| impeccable `PRODUCT.md` | наш `docs/product/mission.md` |
|---|---|
| Users | Для кого |
| Product Purpose | Проблема, Ценность |
| Capabilities and Constraints | Чего продукт НЕ делает, Осознанно нерешённое |
| Product Principles | ближе к `docs/constitution.md` |
| Platform, Positioning, Operating Context, Brand Commitments, Evidence on Hand, Accessibility | — только у него |

**Гипотеза, не проверенная.** До первого `init` завести `docs/PRODUCT.md`:
в нём — только его собственные разделы, а в совпадающих — две строки сути и
ссылка на `mission.md` как на источник. impeccable найдёт файл через
фолбэк `docs/` и, по собственному правилу `init` («update it instead of
creating a competing authority»), обновит его, а не создаст второй.

## 4. План пилота

Сравнить impeccable и `frontend-design` на одной задаче интерфейса, каждый
в своём рабочем дереве. Записать:

1. **Результат** — какой интерфейс лучше и почему. Оценку ставит человек.
2. **Цена** — токены, время, сколько файлов плагин завёл.
3. **Хуки** — уживаются ли с гейтом базы на `Stop`; что упирается в
   подтверждение (`/muagba-base:preflight`, события `wait` в журнале);
   поведение без сети.
4. **`PRODUCT.md`** — проверить гипотезу:
   - (а) не создаёт ли `init` второй файл в корне;
   - (б) переживает ли `docs/PRODUCT.md` frontmatter docsys и не
     переписывает ли его `doctor`;
   - (в) хватает ли ему ссылки на `mission.md` или он начинает её
     дублировать.

## 5. Где пилот

Проект narta согласен рассмотреть, но **не сейчас** (ответ от 2026-09-26):
интерфейса, на котором есть что сравнивать, у них ещё нет — фронтенд из
одной страницы здоровья API, экраны появятся в этапах 2.x. Идёт этап 1.1,
а один запуск — один этап. Установка плагина с бинарником и новый
`docs/PRODUCT.md` — решения их владельца.

Окно — после отчёта этапа 1.1, на первой задаче с экраном (прототип Ганта
или доска). План и пункты (а)–(в) narta возьмёт в работу, когда будет
решение.
