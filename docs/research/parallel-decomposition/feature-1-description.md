# Фича 1. Учебный процесс курса, экзамены, банки задач и «задача курса» (шаг 6 пайплайна создания курса)

Проект: «Наставник» (`/home/rustam/develop/simbioz_team/nastavnik_stage_1`) — платформа, где автор
создаёт курс (бриф → структура компетенций и ступеней → материал → задачи → публикация), а ученик
проходит его уроками А (теория) и Б (практика), треком, пробниками и «Тренажёром ЕГЭ».
Пайплайн создания курса переделывается по концепции 17–18.11 шагами; новое поведение включается
флагом курса `Course.pipeline_v2` («новый путь»), курсы без флага — «старый путь».
Эта фича — один шаг такой переделки.

## Цель

Автор при создании курса выбирает экзамены и настраивает, как курс учит (пробники, домашние
задания, «Тренажёр ЕГЭ»); итоговые задачи цели привязываются к позициям КИМ, целевые умения по
позиции приходят из банка экзамена. Автор выбирает банки задач экзамена и на экране «Задачи»
получает ступени, уже заполненные подходящими задачами банка; генерация LLM дописывает только
недостачу. Свои задачи курса и задачи банка экзамена дальше живут одинаково — как «задачи курса»:
одна таблица размещения (ступень, роль), один приём размещения, один гейт 3, один читатель для
всех потребителей; саму задачу принимают в её банке. Курс не знает, как банк решает задачи, кому
задача видна и откуда она — это отвечает API банка. Параллельно уходит выбор режимов урока: оба
режима есть у каждого курса; старые курсы снимаются с публикации.

## Требования (сжато; полный текст — санированная спека, см. «Документы»)

**А. Учебный процесс курса.**
- Новый пакет `courses/learning_process/` (ярус 3), модель `CourseLearningProcess` рядом с курсом
  (не в снимке брифа): пробники (каждые K ступеней или по расписанию), ДЗ (объём и условие),
  «Тренажёр ЕГЭ», решатель своих задач. Нет строки — умолчания.
- Проверки значений (422 по реестру кодов), общий порядок замков всех записей шага (строка курса
  первой), запись под версией курса вместе с брифом, правка после публикации, заморозка на модерации.
- Чтение в деталях курса на обоих путях; блок «Учебный процесс» в форме создания и в панели брифа
  (только флаг).
- Гейт отправки на проверку: пробники или тренажёр без действующего экзамена — собственный блокер
  `learning-process-exam-missing`, готовность видна заранее.

**Б. Экзамены курса.**
- Каталог автора `GET /api/v1/exam-catalog` — только экзамены с действующей опубликованной версией.
- Список, связать, снять (`/courses/{id}/exams`), права как у правки курса (невидимому — 404),
  версия курса растёт, гонка связывания не даёт 500.
- Экзамены уже в форме создания курса — курс и связи `ExamCourse` одной транзакцией.
- Копирование курса нового пути: учебный процесс, экзамены, банки, связи банка, позиции и образцы,
  а также ступени, их связи с KSA и рёбра графа — одной транзакцией.
- Слияние ответа с несохранённой формой панели; окно «экзамен снят, банк остаётся — снять и банк?».
- Staff `/exam` связи курса с экзаменом только читает; отметку «сверен с версией» курс не ставит.

**В. Выбранные банки экзамена.**
- Пакет `courses/course_bank/`, модель `CourseBank`; список (выбранные и предложения), выбрать,
  снять; решатель своих задач — один вариант «Общий».

**Г. Задачи курса.**
- Модель `CourseTask`: ровно одна ссылка — на задачу банка экзамена с закреплённой ревизией или на
  свою задачу курса (`LearningTask`); ступень, роль (`is_transfer`/`is_trap`), приём размещения.
- Перенос ступени и роли своих задач из `LearningTask` в `CourseTask` миграцией данных и удаление
  этих колонок; до удаления — порт размещения (`course_bank/placement.py`) как единственный путь
  записи, все читатели и писатели (CRUD и API своих задач, генерация и недостача, перекладка ступеней
  шагов 3а/4, гейты и сага, уроки, диалог, импорт, удаление ступеней и тем, решатель, команды, сиды,
  права, тесты) переводятся на порт и читатель сразу, без копии полей.
- Один читатель `course_bank.reader.course_tasks(...)`; принятость задачи банка — функцией банка.
- Раскладка задач банка по ступеням: сама (после гейта 1, при выборе банка, при генерации), Celery без
  ML, занятость под замком строки курса; места ступени (11 / 15 с ДЗ); приоритет «доверенный ответ →
  шаги есть → видна ученикам → разные номера КИМ»; задачи ФИПИ — только верх линии; повтор ничего не
  меняет; отклонённую автором связь не возвращает (и после удаления ступени).
- Кандидаты и ручное добавление, правка и отклонение связи, массовый приём размещения.
- «Принять задачу» и «Принять размещение» для своих задач (сервер и кнопки на экране «Задачи»).
- Гейт 3 по задачам курса: пропускает принятую и в своём банке, и по размещению; блокер
  `course-task-placement-unreviewed`; один счёт недостачи для генерации, «Догенерировать» и гейта 3.
- Переход связей на новые ревизии задачи банка (в том числе смена KSA без ревизии, гонка перехода).
- Отчёт покрытия D-033 (по ступеням, в том числе «банк снят», «ученикам не видна», «ждёт решения в банке»).
- Экран «Задачи»: блок «Задачи из банка», окно ревизий и отчёт покрытия.
- Видимость задач ученикам — только через API банка; курс не читает `origin` и `derived_from`.
- Роли перенос и ловушка: проверки отметок, вид смены, пояснение ловушки, квота переносов по ступени,
  ловушки до каталога ошибок.

**Д. Режимы урока и старые курсы.**
- Все читатели `Course.allowed_lesson_modes` / `prefer_pbl` — константа «оба режима»; запись и
  ответы снимаются (бэкенд и фронт), сторож писателей и читателей; инвариант «линия А без чтения»
  — одной функцией по флагу; проверки режимов ступени — только старый путь; окно ступени на флаге
  без режимов; миграция удаляет колонки.
- Команда снятия старых курсов с публикации и возврата с модерации (`review_rejected`, `--apply`
  только с `--actor`).

**Е. Цель курса и экзамен.**
- `CourseFinalTask` получает `exam_position_refs` и `exemplar_task_ids` (бэкенд и фронт блока
  итоговых задач); «Подобрать умения» по позиции КИМ берёт KSA задач банка на позиции.
- Две автопроверки цели (7.10).

**Нужно от модулей банка экзаменов** (`exam_tasks`, `exam_codifier`, `exam_trainer`, `task_solutions`
ведёт соседняя сессия «банк задач ЕГЭ»; курс в них не пишет; в эксперименте эта работа — часть
фичи): `fipi_task_ids`, пакетные `task_ksa_ids_many` и `positions_for`, `position_task_ksa_ids`,
стойкая к гонке `link_course`, `author_exam_catalog`, `course_exam_links`, CASCADE `ExamCourse.course`,
вход в «Тренажёр ЕГЭ» из курса по настройке учебного процесса, `accepted_task_ids`,
`trusted_answer_task_ids`/`task_states`, выключатель ФИПИ только для задач с собственным
происхождением ФИПИ, фикстура стенда (Е-10). Полный список с условиями — §12 санированной спеки.

**Флаг и мера.** Всё новое — только на флаге; старый путь для курсов без флага работает как раньше
(но побайтно не держится — такие курсы снимаются с публикации).

## Критерии приёмки

AC-1…AC-78 в §7 санированной спеки (каждый — API/тест/UI/SELECT). Главное:
- учебный процесс хранится, проверяется, пишется под версией, правится после публикации (AC-1…AC-7);
- создание с экзаменами одним действием, гейт отправки, каталог, права 404/403, гонка, staff только
  читает (AC-8…AC-18);
- банки, решатель, раскладка сама, не больше мест, приоритет, параллельные прогоны, правило ФИПИ,
  идемпотентность, отклонённая не возвращается (AC-19…AC-32);
- приём размещения, гейт 3, один счёт недостачи, пометка «шаги есть», ревизии, видимость, курс не
  читает `origin`, после публикации банк закрыт (AC-33…AC-42);
- режимов нет, колонки удалены, старые курсы сняты (AC-43…AC-49);
- позиции КИМ, подбор KSA по позиции, автопроверки цели, копирование курса (AC-50…AC-54);
- задача курса: одна ссылка, перенос данных без потерь, ответ API прежний, колонок нет, один писатель,
  два приёма, права, версия за запрос, роли перенос/ловушка, экран «Задачи» (AC-55…AC-78);
- приёмка шага: e2e на стенде `cc-*` (:8092, БД `cc_concept`) и прогон описи шага Р (регресс
  сохранённого функционала, `docs/audits/2026-11-18_course-pipeline-R-inventory/inventory.md`).

## Условия среды (факты проекта, нужны для планирования)

- Полный прогон тестов `courses` — около 11 тыс. тестов, порядка 30 минут; ревью и вливание
  опираются на него.
- Одна линейная цепочка миграций на всё приложение `courses`.
- Генерируемые файлы (карта модулей, факты стека) и реестры кодов, ручек и правил правят многие задачи.
- Правила проекта: исполнитель → независимое ревью → доработка → повторное ревью; e2e на своём стенде;
  ветка задачи от вершины главной ветки плана, вливание `merge --no-ff`, вторая параллельная задача —
  rebase на новую голову; роль `implementer-deep` — для рисков (права, деньги, миграции данных,
  конкурентность).
- Параллельно в той же ветке плана идёт соседняя фича (теория ступени, шаг 8) и работа соседней
  сессии банка ЕГЭ.
