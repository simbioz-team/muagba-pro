# Артефакты фич

Здесь живут артефакты фич. **Конвейер выбирает проект** — свой, Spec Kit,
OpenSpec, BMAD. База ни один из них не несёт: она объявляет интерфейс к нему,
чтобы проверки работали при любом выборе.

## Конвейер фич

Пять строк ниже — то, что читают гейт и хуки. Без них проверять нечего: имя
конвейера само по себе гейту ничего не говорит.

- **Артефакты:** <где лежат файлы фичи и как зовётся файл спеки>
- **Готова к коду:** <по какому признаку видно, что спеку можно брать>
- **Задача → требование:** <как задача ссылается на требование>
- **Готовность ставит:** <кто и когда переводит спеку в готовую>
- **Проверка формы:** <команда; она обязана вызываться из проверки проекта>

Заполненный пример для формы базы:

```
- **Артефакты:** specs/<NNN>-<slug>/ — spec.md, plan.md, tasks.md
- **Готова к коду:** строка `- **status:** active` в spec.md
- **Задача → требование:** ссылка `[R1, R2]` в строке задачи
- **Готовность ставит:** человек, после интервью и снятия всех пометок
- **Проверка формы:** `python3 .claude/tools/check_specs.py`
```

«Готовность ставит» — не формальность. Спеки, написанные без интервью, в
измеренном случае дали 2.7 из 5 по продуктовому качеству: агент заполняет
правдоподобно, и незаданный вопрос исчезает навсегда. Если готовность ставит
агент, запишите это честно — тогда хотя бы видно, чем платим.

**Поле «Проверка формы» обязано называть команду, и команда обязана
вызываться** — из `.claude/check.sh`, `Makefile`, `justfile`, `package.json`
или рабочего процесса CI. Проба это сверяет. «Держится ревью» ответом не
является: договорённость без исполнимой проверки — не гейт, это контракт Э6.

Форма, которую ничего не проверяет, не держится даже у того, кто её придумал:
в проекте, где такую проверку завели, она сразу нашла 23 расхождения в спеках,
написанных часом раньше. А три прогона обкатки базы завели три разные формы и
ни одной проверки — и ни один этого за собой не заметил.

Писать проверку с нуля не нужно: в базе лежит `scripts/check_specs.py` под
форму по умолчанию. Скопируйте его в `.claude/tools/` и подправьте под свою —
форма ваша, и проверка тоже.

## Где живёт состояние задач

Описание задачи и её состояние — разные вещи. Описание лежит здесь. Состояние
(«взято, кем, что осталось») в рабочем дереве жить не может: у каждого дерева
свой checkout, незакоммиченная отметка в соседнее дерево не попадает вовсе, а
закоммиченная остаётся в своей ветке.

Где именно — в `docs/workflow.md`, раздел «Где живут задачи». Проверяет проба
`roles.board`, обоснование — `ADR-0008` базы.

## Форма базы, если своей нет

Берите как есть, дополняйте своими разделами или опишите свою. Это не
единственно верная форма — это работающая по умолчанию.

**`spec.md`**

```
- **status:** draft
```

`draft` — проверяем форму, готовность нет. `active` — ещё и готовность: ни
одной живой пометки `[ТРЕБУЕТ УТОЧНЕНИЯ` вне раздела «Решения по умолчанию»,
и каждое требование покрыто задачей.

Разделы:

- **Зачем** — три фразы: кому, что у него ломается, что станет можно.
- **Сценарии** — каждый доходит до исхода. Вход пользователя → что делает
  система → **что пользователь получает и что с этим делает**. Сценарий,
  обрывающийся на вызове, описывает механику, а не продукт.
- **Требования** — нумерованные, со способом проверки:

  ```
  - R1. КОГДА <условие> СИСТЕМА ДОЛЖНА <поведение>
    Проверка: <чем именно это проверяется>
  ```

- **Критерии приёмки** — продуктовые и измеримые, без упоминания технологий.
  «`check.sh` зелёный» критерием приёмки не является: это условие сдачи кода,
  а не признак того, что человеку стало лучше.
- **Сверка с замыслом** — таблица по образцу сверки с конституцией: пункт
  продуктового документа → как закрыт, либо вне рамок с причиной, либо не
  закрыт и почему. Замысел, не попавший в спеку, не попадёт и в код: агент
  пишет по техзаданию и додумывает остальное.
- **Вне рамок** — в двух частях: «никогда, потому что» и «не в этой фиче».
  Список без причин — оглавление роадмапа, а не граница.
- **Решения по умолчанию** — что приняли, не спросив, и почему это было
  безопасно.

**`plan.md`** — раздел `## Сверка с конституцией` таблицей, где названы все
принципы проекта. При наличии хранилища — ещё `## Расхождения со схемой`.

**`tasks.md`** — задача ссылается на требования и перечисляет файлы:

```
- [ ] T001 <действие> → <проверяемый результат>   [R1, R2]
  Файлы: путь, путь
```

`[R—]` — для задач, не закрывающих требование (подготовка, уборка). Отметка о
выполнении несёт, кто и когда: `- [x] T001 … (implementer, 2026-09-21)`.
Список файлов — то, по чему определяется пересечение задач.
