# Рабочий цикл

Путь задачи от замысла до основной ветки. Агент не наследует разговор:
всё, о чём договорились устно, для него не существует — поэтому договорённость
живёт здесь.

Заполняется на этапе Э6 (жёсткость гейта) и Э9 (остальное).

## Жёсткость гейта

<Лестница из четырёх ступеней, они складываются:
1. просьба в промпте — работает сразу, забывается;
2. `/goal` — условие сессии, перечитывается после каждого хода;
3. `Stop`-хук — ход не закрывается, пока проверка красная;
4. свежий сабагент — оценивает тот, кто не видел рассуждений.
Отметь, какие ступени используются в этом проекте и почему остановились
именно здесь.>

## Откуда берётся задача

<Путь «спека → план → задачи» и где всё это лежит. Плюс признак готовности:
по чему видно, что задачу уже можно брать в работу, а не дописывать на ходу.>

## Условие завершения

<Шаблон условия для `/goal` на типовой задаче.

**Оценщик не запускает команды и не читает файлы** — он судит по тому, что
агент вывел в разговор. Условие пишется так, чтобы вывод самого агента его
доказывал: «`./.claude/check.sh` вышел с кодом 0» работает, «код корректен» —
нет.

Обязательная часть шаблона — граница: «или остановись после N ходов и доложи,
что мешает». Условие без границы это цикл.>

## Кто проверяет

<Место проверяющего в цикле: когда его зовут, что он получает на вход, что
обязан вернуть. Три подтверждения разные, и путать их нельзя:

| Что | Чем подтверждается |
|---|---|
| код собирается, тесты зелёные | `./.claude/check.sh` |
| изменение делает задуманное | прогон живого приложения по рецепту `run-*` |
| ничего лишнего, требования закрыты | свежий агент `reviewer` на дифф |
>

## Где живут задачи

<Где лежит общее состояние задач: что взято, кем, что осталось. Это не то же
самое, что описание задачи, — описание живёт в `specs/`, а состояние
меняется по ходу работы и должно быть видно всем сразу.

Развилка одна и она жёсткая: если агенты работают в отдельных рабочих
деревьях, состояние в рабочем дереве не годится. У каждого дерева свой
checkout — незакоммиченная отметка «взял» в соседнее дерево не попадает
вовсе, закоммиченная остаётся в своей ветке. Файл в репозитории честно
работает ровно для одного агента за раз.

Варианты, из которых выбирают: встроенный общий список задач Claude Code
(состояние в каталоге сессии, захват через файловую блокировку); MCP-сервер
трекера — GitHub Issues, Linear, Jira, Asana, GitLab; файл в репозитории,
если агент работает один.

Закончите раздел строкой-маркером, иначе выбор нельзя проверить машинно:

`Хранилище: <что именно> ← вне дерева`
или
`Хранилище: <что именно> ← в дереве, один агент за раз`

Почему так — `ADR-0008` базы.>

## Когда двое трогают одно

<Что делает агент, обнаружив, что нужный ему файл уже занят другой задачей.
Бесконфликтный случай — два агента в разных файлах — устраивается сам.
Интересен другой: оба правят словарь, схему или один и тот же модуль.

Варианты, из которых выбирают: задачи, пересекающиеся по файлам, не берутся
одновременно (простое и надёжное); пересечение разрешено, и кто пришёл
вторым, перебазируется; общий файл правит только человек. Запишите свой и
скажите, по чему пересечение определяется — по списку файлов в задаче или
как-то ещё.>

<Наблюдаемый признак, по которому объявляют откат, и первое действие. Если
