# Плагины этого проекта

Что включено в `.claude/settings.json` и **почему**. Без причины строку не
добавлять: каждый плагин грузит описания скилов в контекст каждой сессии.

Два класса. **Класс А** — без него не закрывается гейт этапа; ставится молча,
состав не обсуждается. **Класс Б** — обвязка проекта; выбирает человек, по
сработавшему триггеру, с записанным условием снятия.

Прежде чем писать своё, смотрим, есть ли готовое: встроенное в Claude Code,
в официальном маркетплейсе, у сообщества.

## Когда добавлять

<!-- no-question: правило общее для всех проектов, приходит с базой и проектом не заполняется -->

Не авансом, а по сработавшему триггеру. Обоснование придумать легко, и
«осознанно выбранное заранее» — то же самое «на всякий случай», только с
оправданием.

| Триггер | Что добавлять |
|---|---|
| агент ошибся в соглашении дважды | строка в свод правил |
| тот же промпт в третий раз | скил |
| тот же плейбук вставляется в чат | скил |
| «каждый раз без исключений» | хук |
| побочная задача забивает контекст выводом | сабагент |
| второму репозиторию нужна та же обвязка | плагин |

В предложении пять пунктов, иначе решать не из чего: зачем (какой триггер
закрывает), цена в токенах, какие хуки вешает, с чем конфликтует из уже
стоящего, по какому признаку станет ясно, что не нужен.

**Хуки складываются, а не заменяют.** Два плагина, повесивших свой `Stop`,
выполнятся оба.

## Ревизия

<!-- no-question: правило общее, приходит с базой; что именно снято, пишется в «Установлено» -->

На Э10, вместе с разбором накопленного: что из поставленного ни разу не
пригодилось — снять. Без обратного хода набор только растёт, и через полгода
из десяти плагинов работают три, а описания скилов грузятся у всех десяти.

Дело не в токенах. Дело в шуме: когда описаний много и они похожи, агент
берёт не тот скил или не берёт нужный.
